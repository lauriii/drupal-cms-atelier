## What was audited, and what was not

Audited: `recipe.yml`, all 49 files in `config/`, all 97 content entity YAMLs
and the binaries beside them, the three shell scripts and three Python helpers
in `tests/`, the three PHPUnit tests, `composer.json`, `.gitattributes`, and
`README.md`. Categories: correctness, security, performance, test coverage,
tech debt, dependencies, DX, docs, direction.

**Not audited**, deliberately:

- The wider Drupal Canvas codebase. It is not in this repository and its
  problems are not this repository's problems.
- The contents of the compiled build artefacts — `js.compiled` in each
  `config/canvas.js_component.*.yml`, and `css.compiled` in `recipe.yml`'s
  generated block. They are machine output. Their *source* halves
  (`js.original`, `css.original`) were read.
- Anything requiring a running Drupal site. No site was installed, no recipe
  was applied, and `tests/check.sh` was never executed. Every finding below is
  from reading files and running read-only measurements. Where a finding's
  consequence depends on runtime behaviour, its confidence says so.
- Drupal core and contrib module source. Where a finding depends on how core
  behaves (e.g. that default content only copies a binary an entity claims),
  the plan says how to verify it rather than asserting it.

## Findings with no plan

Real, evidenced, and left unplanned because the seven above have more leverage.
Recorded so the next run does not re-derive them. Each names its evidence.

### Worth planning next

1. **`article_teasers` serves full-resolution originals as 176×112 thumbnails.**
   `config/canvas.js_component.article_teasers.yml` uses a raw
   `<img src={article.field_image.uri.url}>` where the other four
   image-rendering components use Canvas's `<Image>` primitive and get a
   derivative from `image.style.canvas_parametrized_width`. `/journal` loads
   3.48 MB of originals. Its wrapper is the only one of the five without that
   image style in its dependencies. **The fix belongs in the paired React
   codebase**, pushed through the Canvas CLI and re-exported — which is why it
   is not plan 006. Plan 006 reduces the cost by ~60% by shrinking the
   originals.
2. **`tests/regenerate-content.sh` exports every entity on the site with no
   ownership filter** (lines 42-50), which is why this repository ships five
   `top-tasks` admin menu links, an unpublished "Privacy policy" node, five
   unreferenced media entities, and `content/file/atelier-logo-4.png` — a mark
   no page renders. All belong to other recipes or to nothing. The fix needs an
   ownership predicate and getting it wrong drops real content, so it wants its
   own plan with its own review.
3. **`tests/check.sh:201-225` — the strongest assertion in the suite can pass
   vacuously.** `component classes resolve in the CSS build` counts unresolved
   classes extracted by a regex over each component's compiled JS. If the regex
   matches nothing — a minifier change, a `cva()` refactor — the count is zero
   and it passes. This is the same fail-open shape the comment at lines 191-192
   describes for a previous assertion. Needs a companion assertion that the
   extracted corpus is non-empty. Deliberately excluded from plan 003, which
   changes how the script *survives*, not what it asserts.
4. **The two self-hosted fonts are addressed by a hardcoded path.** The
   `@font-face` rules inside `recipe.yml`'s generated CSS point at
   `/sites/default/files/atelier-fraunces.woff2` and `…-inter.woff2`. On any
   site whose `file_public_path` is not `sites/default/files` — a multisite, a
   hardened install — both 404 and the display face falls back to Georgia.
   `font-display: swap` means it degrades rather than blocks. Needs either a
   Drupal-side asset library with a resolvable path or a documented caveat.
5. **`composer.json:12` requires `drupal/jsonapi_search_api: ^1.0@RC`, and that
   package has no stable release** — only `1.0.0-rc1` … `rc5` (verified against
   packages.drupal.org). Composer honours inline stability flags only in the
   *root* package, so `composer require drupal/atelier` on a
   `minimum-stability: stable` root may fail to resolve, naming the transitive
   package rather than this template. `tests/src/Kernel/RequirementsTest.php:81`
   only rejects *pinned* constraints, so this passes conformance while
   potentially being uninstallable. Plan 004's CI workflow will surface it on
   first run; its STOP conditions say to report rather than work around it.
   Note that `README.md:360-364` already offers dropping the search stack as an
   option, which would remove the dependency entirely.

### Smaller, verified, low leverage

6. **`recipe.yml:31,26` install `jsonapi_resources` and `consumers`, which
   `composer.json` does not require.** Both are presumably present transitively
   (via `drupal/canvas` and `drupal/simple_oauth`), but the manifest does not
   say so. The day either upstream drops the dependency, the recipe fails at
   install with no hint why.
7. **Two `columns: 3` are YAML integers** —
   `content/canvas_page/41c22c99-…yml:110` and
   `content/canvas_page/5c31bfce-…yml:47` — where
   `config/canvas.js_component.grid.yml:7-12` declares `type: string` with
   `enum: ['2','3','4']` and the other thirteen sites write `'3'`. The shipped
   per-page tree counts in `tests/check.sh:334,336` still match, so the items
   are not being dropped and Drupal is coercing on save; the type drift is real
   and the render impact is unproven. Plan 004 check 7 detects it.
8. **`config/search_api.index.cms_content.yml`: `title_1`** — the Canvas-page
   title field — **is excluded from all four text processors** (`html_filter`,
   `ignorecase`, `stemmer`, `tokenizer` each set `all_fields: false` and list
   only `rendered_item` and `title`). Canvas page titles are indexed as one
   unprocessed case-sensitive token and never get the 3.0 boost node titles
   get. Pages remain findable via `rendered_item`, so it is a relevance defect.
9. **`article_teasers` renders an empty ruled box when filtering empties the
   list.** The "No articles published yet" guard tests the *unfiltered*
   response, then the render filters out the current article. On a site with
   one journal entry, the empty-state branch is skipped and two hairline rules
   paint with nothing between them.
10. **Three wrappers carry version blocks no tree references** —
    `canvas.component.js.cta.yml`, `post_meta.yml`, `section_intro.yml`. Unlike
    the `button` case plan 005 fixes, these genuinely differ from `active` and
    nothing points at them. Left alone deliberately: they are Canvas's own
    serialisation of version history, and hand-editing generated files is the
    failure mode plan 005 exists to reduce.
11. **`tests/lib/source-images.py` swallows every exception** (`except
    Exception: continue`), so an auth rejection, a network failure and an
    unreadable image are indistinguishable from "did not match the brief", and
    the script reports `in brief: 0`. Plan 001 fixes the crash on its last line
    and the credential; the over-broad `except` is left.
12. **`tests/lib/measure-images.py` and `tests/lib/source-images.py` duplicate
    ~15 lines of colour maths**, including a duplicated `LUM`/`SAT`/`HUE` band
    that can silently diverge. Plan 001 explicitly defers this to keep a
    security diff minimal.
13. **`.gitattributes` marks `/tests export-ignore`**, so nobody who installs
    via `composer require drupal/atelier` receives `tests/lib/measure-images.py`
    — the tool `README.md:182-185` and `README.md:310` tell adopters to use when
    replacing the photography, which `README.md:196` calls the template's
    largest outstanding job. Either move the measuring tools out of `tests/`, or
    say in the README that they live in the git repository only.
14. **Documentation drift beyond what the plans fix.** `README.md:154-162`
    describes four pages where ten ship (`README.md:150-152` says ten in the
    sentence above the list); `README.md:574` says "all four pages";
    `tests/check.sh:311-312` and `tests/regenerate-content.sh:59` both say
    "three posts" where six articles ship; `README.md:606` says
    `RequirementsTest.php` is "unmodified from the canonical version" without
    naming which version, and that file's own line 21 references a
    `GET-STARTED.md` that is not in this repository.
15. **`tests/src/Functional/ValidationTest.php:94-97` skips its own assertion**
    when `getComponent()` returns NULL — the case it exists to catch. Add
    `assertNotNull` before dereferencing. Also `assertCanvasComponentsAreIncluded()`
    performs zero assertions if no component-tree entities loaded, so it cannot
    distinguish "all good" from "nothing was imported".
16. **`tests/src/Functional/InstallTest.php:41-43`** is
    `$this->expectNotToPerformAssertions()`. That is the canonical shape and not
    a defect, but it means only one of the three PHPUnit tests asserts anything
    about *this* template specifically.

### Security posture, documented rather than fixed

17. **`recipe.yml:142-145` grants `content_editor` the `administer code
    components` and `administer page template` permissions.** What that
    administers is React source that executes in every visitor's browser on
    every page, plus the site-wide stylesheet. That is an admin-equivalent
    trust decision. `README.md:71-75` documents the grant but frames it purely
    as convenience and never states the privilege it confers. The grant is
    plausibly right for this template — it is the whole point of it — but an
    adopter adding a junior editor to `content_editor` deserves to be told.
    Worth a README paragraph, not a config change.
18. **`config/search_api.index.cms_content.yml` has no `content_access`
    processor.** On a stock install the `entity_status` processor is adequate.
    The moment an adopter adds any node-access module, published-but-restricted
    nodes keep appearing in anonymous `/jsonapi/index/cms_content` results with
    title and URL. `rendered_item` is rendered as the anonymous role, which
    correctly limits this to metadata. Hardening, conditional on a change the
    adopter makes.
19. **`README.md:426-428` passes an OAuth client secret as a `curl -d`
    argument**, which is visible in shell history and the process table. The
    surrounding documentation is otherwise careful: no key material, no
    consumer entity and no client secret ships anywhere in the repository, and
    `README.md:384-389`'s stated reason for that is honoured in full.

## Direction — options for the maintainer, not defects

Four grounded options, each citing repository evidence. These are choices, not
problems, and they are listed after the findings deliberately.

1. **Settle the photography by removing it, not by re-encoding it.**
   `README.md:302-307` already names licensing as "the real gate" — the
   Unsplash License is permissive but not GPL, and drupal.org wants
   GPL-compatible — and offers the answer: "Shipping with no stock photography
   is the clean answer." The set also fails the template's own photographic
   brief 15-of-27 (`README.md:193`), and it is 13 MB of a 14 MB package. One
   decision closes the licensing gate, the size gate, the brief admission and
   most of the performance findings. **Trade-off**: a fresh install with no
   photographs undercuts `README.md:130`'s central claim that the template "is
   not a backend waiting to be filled in". A middle path — six to eight images
   at 1200px covering the hero and one figure row — keeps the first impression
   at roughly 1 MB. Effort: M, coarse. If this is the direction, do it *instead
   of* plan 006, not after it.
2. **Make the snapshot reproducible before anything else touches the front
   end.** `README.md:643-651` argues that vendoring code components is
   unprecedented among site templates and that this is acceptable "so the
   snapshot is generated by `tests/regenerate-components.sh` rather than
   hand-maintained". That justification is load-bearing and currently
   unverifiable by a second party: the script runs only inside DDEV, only at
   `/var/www/html`, only for a directory named `atelier`, and records nothing
   about what it exported. Plan 005 is the first step; the fuller version is a
   documented, reproducible refresh loop that a contributor who is not the
   author can run. **Trade-off**: unglamorous work with no user-visible value,
   right up until someone else needs to change a component. The honest
   alternative is to write down that this is a single-maintainer template.
   Effort: M, coarse.
3. **Either ship a search component or drop the search stack.**
   `README.md:360-364` states the position: `search_api`, `search_api_db` and
   `jsonapi_search_api` install a `cms_content` index that no shipped component
   queries, and "Drop them from `recipe.yml` if you would rather not carry
   them." The index is not perfunctory — it enables the
   `canvas_component_tree_inputs` processor specifically so text an author
   typed into a component's props is searchable, and it configures highlighting
   with excerpts. A 22nd component querying it would be the strongest possible
   demonstration of this template's own argument (`README.md:348-351`: that
   `site_nav` and `article_teasers` "prove the argument for code components
   over a static library" because they read live Drupal data). **Trade-off**:
   the index exposes two title fields, one per datasource, so the component
   must merge two result shapes — more logic than any existing component
   carries; and adding one moves `README.md:322`'s "Twenty-one, and no more"
   from a principle to a number. Dropping the stack costs nothing and removes
   finding 5 above outright. Effort: M to build, S to delete.
4. **Productise "change one component".** `README.md:456-503` is the authoring
   path and it lists six distinct ways the Canvas CLI will reject a component,
   each of which costs a round trip to discover: `component.yml` needing
   `machineName`/`status`/top-level `required`; prop titles matching camel
   case; `@/lib/utils` imports forbidden; array-of-object props unsupported;
   slots arriving as a named prop rather than `children`; and `<ul>`/`<li>`
   around a slot not surviving the parser. All six are mechanically checkable.
   A small `tests/lib/lint-component.py`, following the conventions already
   established in that directory, would serve adopters and this template's own
   regeneration loop. **Trade-off**: most of this arguably belongs in the
   Canvas CLI rather than in a site template — but the CLI is not in this
   repository and the friction is. Effort: M, coarse. A cheaper companion: a
   README paragraph telling a site owner what re-applying the recipe does to
   components they have edited in Canvas, which today is silent replacement.

## Findings considered and rejected

Recorded with reasoning so they are not re-audited next run.

- **URL-scheme sanitising in `button`, `figure`, `logo` and `site_nav` `href`s.**
  Reported as a stored-XSS sink. It is not: every `url` prop is derived as a
  Drupal `link` field (`field_type: link`, `link_type: 17` — see
  `config/canvas.component.js.button.yml:31-37` and the same in `figure` and
  `logo`), so `LinkExternalProtocolsConstraint` rejects `javascript:` and
  anything outside core's allowed-protocol list server-side. Platform
  behaviour, not a defect.
- **The two footer privacy links.** `content/menu_link_content/d393a906-…yml`
  ("Privacy policy" → an unpublished node) and `a1f7c204-…yml` ("Privacy" → the
  shipped `/privacy` Canvas page) both ship enabled. Commit `cfc17de`'s message
  documents this explicitly: the base recipe ships a link with the same UUID,
  default content skips entities that already exist, and "the base recipe's
  link stays but never renders: JSON:API filters it out for anonymous visitors
  because its target is unpublished." A documented decision. (The *cause* —
  unfiltered content re-export — is finding 2 above and is worth fixing.)
- **`site_nav` rendering only two menu levels.** `README.md:345` documents
  exactly that: "Renders two levels, and marks the current page." Documented
  scope, not a dropped requirement.
- **No anti-spam on the anonymous contact form.** The base recipe
  `drupal_cms_site_template_base` applies `drupal_cms_anti_spam`. Already
  covered.
- **`badge` shipping unused by the demo.** `tests/check.sh:534-547` is an
  explicit decision record: it was placed twice, read as a disabled control
  both times, and the coverage floor was deliberately set to 20-of-21 rather
  than forcing a bad placement. Leave it.
- **Splitting the compiled CSS out of `recipe.yml`.** `recipe.yml:125-131` and
  `tests/regenerate-components.sh:21-30` both document why it must be a
  `setProperties` action: `canvas.asset_library.global` already exists when
  this recipe's config imports, and the `strict:` workaround is a documented
  trap. The mechanism is correct. (Reviewability of a 43 KB two-line diff is a
  real cost, but the fix — also writing the decoded CSS to a checked-in file
  purely for diffing — is cosmetic and was not worth a plan.)
- **`tests/lib/measure-images.py` always exiting 0.** Lines 60-62 explain the
  choice: "a failing exit code here would only teach whoever runs it to pass
  `--force`."
- **Component JavaScript bundle size.** Measured: 31 KB uncompressed across all
  21 compiled components, 12–25 KB on the heaviest page, with every shared
  helper imported from `drupal-canvas` as an external rather than re-bundled.
  Not a problem. The images are.
- **`article_teasers` over-fetching from JSON:API.** It uses sparse fieldsets on
  both resource types, an explicit include, a sort and a page limit. Disciplined.
  (It does fetch `body` unconditionally even when the `excerpt` prop is off,
  which is minor and is noted under finding 1's neighbourhood.)
- **`curl -sk` and `AGENT_BROWSER_IGNORE_HTTPS_ERRORS=1` in `tests/check.sh`.**
  TLS verification disabled against a local disposable site with an mkcert
  certificate. Local development convention; no production path.
- **`--account-pass=admin` at `tests/check.sh:44`.** A throwaway credential for
  a database the same script drops and rebuilds.
- **Prompt-injection content.** Four independent sweeps of every source,
  comment, config `label`/`description`, content body and doc file found
  nothing instruction-shaped aimed at tooling. Recorded because this repository
  was built by an autonomous agent and a clean negative is the useful result.
