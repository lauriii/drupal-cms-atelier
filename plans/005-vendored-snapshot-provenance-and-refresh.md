## Why this matters

The 21 files in `config/canvas.js_component.*.yml` are the *entire front end*
of every site installed from this template. They are a vendored snapshot,
exported from a separate React/Tailwind codebase that this repository does not
contain and does not name.

Nothing in the repository records what that snapshot is a snapshot **of**. No
upstream URL, no commit SHA, no CLI version, no export timestamp — I searched
every tracked file. `README.md:12-15` names the upstream only as a category
("a React and Tailwind project generated by `npx @drupal-canvas/create`").

The consequence is not abstract. A second maintainer cannot answer "is this
stale?", cannot diff against upstream, cannot reproduce the export, and cannot
tell whether a bug they are looking at was already fixed upstream. And the
script `README.md:625-628` calls "the mechanism that keeps the vendored
snapshot honest" — `tests/regenerate-components.sh` — is not runnable by anyone
but its author: it deletes 45 config files from a *host* path derived
portably, then writes the replacements to a *container* path hardcoded as
`/var/www/html/recipes/atelier/config`, and then shells out to `ddev` by name.
On any other layout it deletes the snapshot and writes nowhere.

The drift this predicts has already happened: the header page region pins
`js.button` at a version that is not the wrapper's active one, and three other
wrappers carry version blocks that no tree references. Nothing in the test
suite can see either.

### Step 2: Stop the export writing to a hardcoded container path

The PHP at lines 59-77 should not know any path at all. Have it print the
config files to stdout as a single stream the host writes, so the only
filesystem the script touches is the one `RECIPE_DIR` points at.

Change the `drush ev` body to emit a `----FILE:<name>----` delimited stream:

```bash
$DRUSH ev '
foreach (["js_component", "page_region", "component"] as $type) {
  foreach (\Drupal::entityTypeManager()->getStorage($type)->loadMultiple() as $entity) {
    // Only the wrappers for our own code components; Canvas regenerates the
    // block and SDC ones from whatever else the site has installed.
    if ($type === "component" && !str_starts_with($entity->id(), "js.")) {
      continue;
    }
    $data = $entity->toArray();
    unset($data["uuid"], $data["_core"]);
    $name = $entity->getEntityType()->getConfigPrefix() . "." . $entity->id();
    print "----FILE:$name.yml----\n";
    print \Symfony\Component\Yaml\Yaml::dump($data, 8, 2);
  }
}
' > "$STAGING/stream.txt"
```

and split it on the host with a short Python block, following the style of the
existing `python3 - "$RECIPE_DIR" <<'PY'` blocks in this file.

**Stage before you delete.** Write into a `mktemp -d` staging directory first,
count what arrived, and only then remove the old files and move the new ones
into place:

```bash
STAGING="$(mktemp -d)"
trap 'rm -rf "$STAGING"' EXIT
```

with the deletion moved to *after* a successful, non-empty export:

```bash
written="$(ls "$STAGING"/*.yml 2>/dev/null | wc -l | tr -d ' ')"
if (( written < shipped_components + shipped_regions )); then
  echo "Refusing to replace the snapshot: the export produced $written files." >&2
  echo "Expected at least $(( shipped_components + shipped_regions )). Nothing has been deleted." >&2
  exit 1
fi
rm -f "$CONFIG_DIR"/canvas.js_component.*.yml "$CONFIG_DIR"/canvas.page_region.*.yml "$CONFIG_DIR"/canvas.component.js.*.yml
mv "$STAGING"/*.yml "$CONFIG_DIR"/
echo "    wrote $written config files"
```

This is the substantive safety change in the plan: today the script deletes
first and hopes. The header comment at lines 37-42 says that has already cost
the header and footer configs once.

**Verify**:
- `bash -n tests/regenerate-components.sh` → exit 0
- `grep -n '/var/www/html' tests/regenerate-components.sh` → no matches
- `grep -n 'mktemp -d' tests/regenerate-components.sh` → one match
- The `rm -f` line appears **after** the `written` guard:
  `awk '/written=/{w=NR} /rm -f "\$CONFIG_DIR"/{r=NR} END{print (w<r) ? "ok" : "WRONG ORDER"}' tests/regenerate-components.sh`
  → `ok`

### Step 5: Record the snapshot's provenance

Add an `extra.atelier.snapshot` block to `composer.json`. Put it beside the
existing `extra.drupal-site-template` key, not inside it — that key belongs to
`drupal/site_template_helper` and adding foreign data to it risks confusing
that plugin.

```json
        "atelier": {
            "snapshot": {
                "_comment": "What the vendored code components in config/canvas.js_component.*.yml are a snapshot of. Regenerated by tests/regenerate-components.sh; fill every field or the snapshot is not reproducible.",
                "upstream": "",
                "upstream-revision": "",
                "canvas-cli": "",
                "drupal-canvas": "",
                "exported": ""
            }
        }
```

Then have `tests/regenerate-components.sh` fill it on every run. Add a step
after the splice that reads the Canvas module version from the site and stamps
the block:

```bash
echo "==> Stamping the snapshot's provenance"
canvas_version="$($DRUSH ev 'print \Drupal::service("extension.list.module")->getExtensionInfo("canvas")["version"] ?? "unknown";' 2>/dev/null | tr -d '[:space:]' || true)"
python3 - "$RECIPE_DIR" "${ATELIER_UPSTREAM:-}" "${ATELIER_UPSTREAM_REVISION:-}" "${ATELIER_CANVAS_CLI:-}" "$canvas_version" <<'PY'
import json, pathlib, sys, datetime
root, upstream, revision, cli, canvas = sys.argv[1:6]
path = pathlib.Path(root) / 'composer.json'
data = json.loads(path.read_text())
snap = data.setdefault('extra', {}).setdefault('atelier', {}).setdefault('snapshot', {})
if upstream: snap['upstream'] = upstream
if revision: snap['upstream-revision'] = revision
if cli: snap['canvas-cli'] = cli
snap['drupal-canvas'] = canvas
snap['exported'] = datetime.date.today().isoformat()
path.write_text(json.dumps(data, indent=4) + '\n')
missing = [k for k in ('upstream', 'upstream-revision', 'canvas-cli') if not snap.get(k)]
if missing:
    print('    WARNING: provenance incomplete, set ' +
          ', '.join('ATELIER_' + m.upper().replace('-', '_') for m in missing))
else:
    print('    stamped provenance')
PY
```

A warning rather than a hard failure: the maintainer running this has just
exported a working snapshot, and refusing to write it because an environment
variable was unset would push them toward bypassing the script entirely.
